# Agent Demo Suite 是干什么的

## 一句话

**一个可观测、可审批、可回放的 Agent 运行时样板**：把一次 Agent 运行拆成
“建 run → 出计划 → 逐步执行 → 工具调用需审批 → 留事件与检查点”，
外加一条多模态数据与训练实验的流水线。

## 它要解决的问题

很多人写 Agent 是“一个 while 循环 + 一堆工具”，上线前才发现三件事没法回答：

| 必须能回答的问题 | Suite 的做法 |
| --- | --- |
| 这次运行到底干了什么？ | 每次运行是一等公民（`run_id`），产生 `run.created / plan.created / task.*` 等事件 |
| 危险工具谁批准了？ | 工具带 `permission` 与 `requires_human_confirmation`；未批准的调用挂起成 approval，等你批/拒 |
| 挂了能不能续？ | 检查点 + resume；事件可导出成 JSONL 做离线分析 |
| 训练数据从哪来、怎么比对？ | 多模态数据集（版本、切分）+ 实验记录（rank/alpha/lr/epochs/量化位宽）+ 与基线对比 |

## 不做什么（边界）

- 不是产品级平台：没有账号、没有多租户、没有数据库集群，只有本地事件存储。
- planner 是**确定性**的（`planner_version: deterministic/1`），不是 LLM 规划；
  它演示的是“运行时的契约”，而不是“更聪明的规划”。
- 多模态实验默认使用 `UnavailableRunner`：没有训练环境时，指标如实显示不可用，**不编造数字**。

## 怎么用（两分钟走通一条链路）

1. **建一次运行**：填任务描述（例如“读上下文并回显”），拿到 `run_id`。
2. **看计划**：`GET /runs/{id}/plan` 会返回 `TaskPlan`（goal + tasks）。
3. **执行**：点执行，状态从 `created → running → completed`，任务的 `output` 在这里产生。
4. **看轨迹**：事件时间线 + 摘要（耗时、任务数、成功率、token）。
5. **试审批**：对需要确认的工具发起调用，会拿到 approval，批准或拒绝后再看结果。
6. **多模态**：建数据集 → 上传文件（base64）→ 冻结版本 → 切分 → 建实验 → 与基线对比。

## 界面怎么读

http://127.0.0.1:8003 是一个“工程仪表盘”：

```
左：一次运行的流程条（created → running → completed / failed / cancelled）
中：计划与任务表（每个任务的状态、输出、重试次数）
右：事件流与摘要（耗时、成功率、token 成本）
下：工具与审批（哪些工具需要人工确认）
最下：多模态数据集与实验（可折叠）
```

- 界面上每个数字都来自 `/api` 的真实返回；`tokens` 显示 `null` 是因为没接真实模型，
  不是 bug。
- 想验证“审批真的拦得住”，去工具区发起一个 `requires_human_confirmation: true` 的调用。
